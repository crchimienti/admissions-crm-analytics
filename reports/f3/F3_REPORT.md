## Eligibility, fields and ratios

For the admissions profile, record_origin = original is exactly the F0 eligibility (is_duplicate = false and is_reactivation = false): the mapping derives record_origin from the two flags and rejects rows with both. tests/test_kpi_eligibility.py and tests/test_kpi_requirements.py check the equivalence on the generated data (against the F0 loader), on the canonical path (CSV -> canonical -> adapter), on the 12-record fixture and on all five fixture variants; an unknown or null origin is a data error (E_ENUM in the contract, K_FIELD_VALUE in the engine) and a missing origin field is FLD, so no record enters eligible silently. It is a profile rule, not an engine rule.

No field is assumed available: a field not provided gives FLD with the exact missing fields, combined with HM, HF, AUT, APT, DEN0, INSUF or ORD when relevant. Ratios need the same unit and a declared relation (subset_of, same_base, independent_allowed); forms_over_interviews_held is same_base.
